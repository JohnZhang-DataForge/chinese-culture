# Information Architecture

**Status:** Proposed

## Primary information domains

- **Learn:** structured entry-level courses and lessons.
- **Culture:** topical articles about arts, daily life, philosophy, history and traditions.
- **Festivals:** celebration explainers and their cultural backgrounds.
- **Books:** reading guides, reading levels and legitimate access links.
- **Events:** scheduled announcements, distinct from evergreen festival explanations.
- **About:** mission, editorial approach, sources and contact.

## Content types

| Type | Purpose | Key relationship |
|---|---|---|
| Article | Standalone cultural explanation | Topic and related articles |
| Lesson | Step in a learning path | Course, order, next lesson |
| Course | Ordered learning sequence | Lessons and level |
| Festival | Evergreen cultural reference | Traditions, region, related events |
| Book guide | Contextual reading recommendation | Author, translation, reading level |
| Event | Date-and-place-specific announcement | Organizer, date, location, status |
| Landing page | Curated navigation to content | Featured entities in a section |

## Hierarchy

Keep the navigation shallow: a top-level section → category or learning path → detail page. Avoid identical content copied under several sections; link or tag it instead.

## Relationship rules

A festival page is permanent even when there is no scheduled event. An event links to the festival only when directly relevant. A book guide must not imply that the full copyrighted book can be downloaded.

## Naming

Use descriptive English names for menus; keep romanization consistent; show Simplified and optionally Traditional characters in learning content; explain translated terms instead of relying on transliteration alone.

## Acceptance

A visitor can reach any core content type from the home page within a few intentional navigation steps, and every detail page offers a relevant next action.
